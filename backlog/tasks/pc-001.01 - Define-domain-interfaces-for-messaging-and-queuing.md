## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Create two new domain interface libraries following the existing pattern (presence-cube.domain.repositories). The messaging interface (message_listener.h) abstracts transport-specific message reception with initialize/subscribe/start/stop operations. The queuing interface (command_queue.h) abstracts platform-specific queue implementations with initialize/enqueue/dequeue/destroy operations. Both must include _func.h files with function pointer typedefs for dependency injection, matching the existing get_led_repository_func.h pattern. These are header-only libraries with no .c files — each needs a library.json manifest with srcFilter: "+<*.h>".
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 message_listener.h declares initialize, subscribe (topic + callback), start, and stop functions
- [ ] #2 message_listener_func.h defines function pointer typedefs for all message_listener functions and the on_message callback
- [ ] #3 command_queue.h declares initialize (with capacity), enqueue (returns bool), dequeue (with timeout, returns length), and destroy functions
- [ ] #4 command_queue_func.h defines function pointer typedefs for all command_queue functions
- [ ] #5 Both libraries have library.json manifests following the presence-cube.domain.repositories pattern (header-only, srcFilter: +<*.h>)
- [ ] #6 Neither interface references any specific transport protocol or concurrency mechanism
<!-- AC:END -->
